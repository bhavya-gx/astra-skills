# Playful Explainer

**Structure:** Familiar analogy → mechanism → limit → example. Aim for 30–45 seconds after reading aloud; shorten to your natural pace.

## Fill-in spoken script

[CONCEPT] sounds complicated. Think of it like [FAMILIAR THING].

Normally, [EVERYDAY EXAMPLE].

This works by [PLAIN-LANGUAGE MECHANISM].

The difference is [WHERE THE ANALOGY STOPS BEING ACCURATE].

For example, [ONE SPECIFIC USE CASE].

That matters because [BENEFIT OR CHANGE FOR THE VIEWER].

[ONE QUESTION OR CALL TO ACTION]

## Ready-to-adapt example

The names and product in these examples are fictional; this is demonstration copy, not reporting. General AI behaviour should be checked against the particular product you discuss.

An AI assistant's memory can sound mysterious. Think of it like a notebook on your desk.

If you write down the context for a project, you do not have to explain the whole project every time you return to it.

Some assistants can use saved information in a similar way: they bring relevant context into a later conversation.

But the notebook comparison has a limit. What gets stored, how it is retrieved, and what you can control depend on the product.

A practical example is keeping your preferred writing style available for the next draft.

Useful context saves repetition. Checking that context still matters.

What would you want an assistant to remember?

## On-screen beats

| Card | Detail |
| --- | --- |
| The analogy | a notebook for useful context |
| The limit | behaviour depends on the product |
| The use case | bring a writing style to the next draft |

Record the script first. Use the transcript to put these cards on the right phrases; a script alone does not establish subtitle timing. Keep each card short, and end with one clear action.
